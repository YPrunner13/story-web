# 기획문서 (PRD) — AI 업무 자동화 앱 (가칭: **AutoMate**)

> 작성일: 2026-06-16
> 상태: 초안 v0.1 (MVP 정의 단계)

---

## 1. 한 줄 정의

> **"주제만 던지면, 내 콘텐츠가 알아서 만들어진다."**
> 일은 AI가 대신하고, 사용자는 자기 시간을 지키면서 결과(수익·결과물)를 얻는 AI 업무 자동화 앱.

---

## 2. 배경 — 왜 지금, 이 제품인가

### 2.1 시장 인사이트 (2026)

요즘 20대(Gen Z·MZ)의 행동 패턴을 추적하면 하나의 결론으로 수렴한다:

1. **돈은 벌고 싶지만, 몸 쓰고 시간 뺏기는 건 싫다.**
   - Gen Z의 72%가 부업(사이드 허슬) 중 → 단, "시간을 파는 노동"이 아니라 "저노력·자동화" 방식을 선호.
2. **그래서 뜬 게 "앱테크 / 패시브 인컴"** → 한 단계 더 나아가면 **"내 일을 대신 해주는 자동화"** 수요.
3. **2026 부업 패러다임 전환**: "시간을 파는 노동" → **"AI로 시스템을 구축"**.
   - 페이스리스 콘텐츠 $500~10,000/월, AI 콘텐츠 라이팅 $2,000~8,000/월 등 검증된 수익 모델.

### 2.2 빈틈 (Opportunity)

- 자동화 부업을 시작한 사람의 **80%가 30~60일 내 포기.** 이유 = "세팅·관리가 여전히 어렵다."
- 즉 진짜 먹히는 제품은 **"자동화를 대신 세팅·관리해주는 자동화"** — 사용자는 진짜로 손을 거의 안 댄다.

---

## 3. 타겟 & 페르소나

| | **일반 사용자 (Free)** | **개인 사업가 (Pro)** |
|---|---|---|
| 정체성 | 일상·부업에 관심 있는 20대 | 1인 창업자·소상공인·프리랜서 |
| 핵심 욕구 | "잡일은 줄이고 콘텐츠로 수익은 내고 싶다" | "직원 없이 마케팅·운영을 자동화하고 싶다" |
| 지불 의향 | 낮음 (무료로 습관화) | 높음 (시간=비용, 구독 결제) |
| 진입 경로 | 개인 SNS·블로그 자동화 | 비즈니스 마케팅·다중 채널 자동화 |

**전략:** 일반 사용자로 습관을 들이게 한 뒤, 수익화·사업 욕구가 생기면 **Pro로 자연 업셀.** (토스·노션이 쓴 검증된 Freemium 전략)

---

## 4. 핵심 가치 제안 (Value Proposition)

- **시간 절약:** 콘텐츠 1건 30분 → 30초.
- **결과가 눈에 보임:** 생성 즉시 미리보기 → "오 이거 된다" 체감 → 전환.
- **손 안 대도 굴러감:** 예약 발행·자동 반복(Pro)으로 진짜 패시브에 근접.

---

## 5. 제품 컨셉 — Freemium 2단계

> **같은 엔진, 다른 포장.** 핵심 생성 엔진은 하나, 권한·규모·자동화 깊이로 Free/Pro를 가른다.

### 5.1 MVP 첫 자동화 = **콘텐츠 자동 생성**

선정 이유:
- 시장 가설("시간 안 쓰고 수익")에 가장 정확히 부합.
- 만들기 가장 쉽고, **결과물이 즉시 보여** 데모·전환에 유리.
- Free→Pro 분리가 가장 자연스러움.

### 5.2 기능 분리

| 기능 | **Free (일반앱)** | **Pro (프로앱)** |
|---|---|---|
| 콘텐츠 생성 | 일 N건 제한 | 무제한 |
| 채널 | 1개 (예: 인스타 캡션) | 멀티 채널 (인스타·블로그·X·스레드 등) |
| 브랜드 톤 | 기본 톤 | 브랜드 보이스 학습·고정 |
| 이미지 | 기본 | 고급/일관 스타일 |
| 예약 발행 | ❌ | ✅ 스케줄·자동 반복 |
| 다중 에이전트 워크플로 | ❌ | ✅ (주제 발굴→생성→발행 자동) |
| 결과 분석 | ❌ | ✅ 성과 리포트 |

---

## 6. 수익 모델

- **Freemium + 구독(인앱 결제).** Free로 유입·습관화 → Pro 월 구독으로 전환.
- 웹 MVP에서는 **Stripe 구독**으로 시작 (모바일 확장 시 앱스토어 인앱결제).
- 보조: 사용량 기반 크레딧(생성 횟수) 모델 병행 검토.

---

## 7. 기술 아키텍처 (웹 우선 · 모바일 확장 가능)

```
[ 클라이언트: Next.js (웹, 반응형) ]
        │  (모바일 확장 시 RN/Expo 또는 PWA — 핵심 로직 재사용)
        ▼
[ API / 백엔드: Next.js Route Handlers ]
        │
        ├── 인증: Auth (이메일/소셜)
        ├── 결제: Stripe (Free/Pro 티어 게이팅)
        ├── DB: Postgres (유저·구독·생성 기록)
        └── 자동화 엔진
                ├── LLM: Claude API (콘텐츠 생성 — 최신 모델 사용)
                ├── 잡 스케줄러 (예약 발행 — Pro)
                └── 채널 연동 (SNS 발행 API)
```

**원칙:**
- 핵심 비즈니스 로직은 클라이언트와 분리 → 추후 모바일 클라이언트가 같은 API 재사용.
- 티어 게이팅(Free/Pro)은 서버에서 강제.

---

## 8. 핵심 사용자 플로우 (MVP)

1. 가입 (Free) → 2. 주제/키워드 입력 → 3. AI가 콘텐츠 초안 생성 (즉시 미리보기) →
4. 수정·복사 → 5. (Pro 유도) "예약 발행·멀티채널은 Pro에서" → 6. 업그레이드 결제.

---

## 9. 성공 지표 (KPI)

- 활성화: 가입 후 첫 콘텐츠 생성률.
- 습관화: 주간 재방문·생성 빈도.
- 수익화: **Free→Pro 전환율**, Pro 유지율(리텐션).
- 가설 검증 지표: "내가 직접 했으면 걸렸을 시간" 절감량.
